# 快捷按钮矩阵细则（V0.10）

本技能把每项能力封装成中文 slash command（快捷按钮），让你不用记英文、不用两步操作。本文件记录完整清单、适用边界、安装与排错、项目速记机制。

## 1. 设计原则（三条）

1. **按钮即入口，不用两步**：斜杠命令本身就是入口，命令内容里写明"使用 cht-work-skill 的第 X 步 / 某工具"，Agent 读到后自动按技能规则执行。**没有"先打开技能再敲命令"这一步**——技能是被引用加载的规则集合，不是要先启动的程序。
2. **按钮不拆技能**：按钮只是"快捷入口"，指向本技能的能力。技能本体及其集成的两个上游子技能（frontend-slides 163 文件 / guizang-ppt-skill 43 文件）完整保留，不删不改。
3. **一项能力一个按钮，不碎片化**：只给"用户会单独调用"的能力建按钮；内部执行能力（UFO 编排、Ponytail 阶梯、分叉机制）是各步内部规则，不单独建按钮，避免按钮泛滥。

## 3. 项目速记机制（`/改` `/fix`）

解决"每次改同一项目都要重报路径"的痛点。

- **存储位置**：`~/.codebuddy/command-projects.md`，仓库模板为 `commands/项目速记-示例.md`。
- **表结构**：别名 | 类型 | 项目路径 | 启动命令 | 页面 URL。
- **匹配流程**：`/改 报价器按钮改成蓝色` → 读速记表 → 别名"报价器"模糊命中 → 取类型映射到工具（网页→Pinta）、取路径/启动命令/URL → 说一句"已按速记『报价器』走改网页" → 直接执行，**不弹选择框、不问路径**。
- **未命中**：弹三选一选择框；用户给了路径就执行完顺手补一行，下次即命中。
- **唯一一次输入**：路径是用户机器上的信息（工作区里没有），Agent 无法自取，所以首次需用户提供一次，之后永久记住。
- **示例行非真实**：`commands/项目速记-示例.md` 里的 `/path/to/quotation-app` 是格式样例，明确标注不许当真实路径启动。

## 4. 安装与生效

```bash
# 在仓库根目录执行，把 12 个按钮装到 ~/.codebuddy/commands/
bash scripts/install-commands.sh
# 想装到自定义目录
bash scripts/install-commands.sh /your/path/commands
```

装完在会话执行 `/reload-plugins`（平台内置命令，需用户手动触发，Agent 无法代执行）让命令生效。

脚本行为：复制 `commands/*.md` 到目标目录，`项目速记-示例.md` 作为模板跳过安装，输出每个已装按钮对应的 `/命令名`。

## 5. 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 敲 `/改` 没反应 | 命令未重新扫描 | 会话里执行 `/reload-plugins` |
| 中文命令名不显示 | 客户端斜杠解析器不认中文名 | 用英文保底 `/fix` |
| 敲按钮后还要手动打开技能 | 误解：技能不是要打开的 | 按钮已内含技能调用，直接等 Agent 干活即可 |
| 每次都要重报项目路径 | 未用速记 / 未命中别名 | 首次报路径后会自动补记；确认别名一致 |
| 反馈工具连不上 | 扩展/companion 未装或未在正确目录 | 按各按钮内步骤装；工具是可选依赖，不装不影响 PPT 生成 |

## 6. 与前五步的关系

按钮是**入口层**，前五步是**执行逻辑**——按钮调起后，Agent 仍按 `SKILL.md` 的五步规则干活：

- `/ppt` → 调完整六步（素材→优化→检索→选路线→编排→反馈）；
- `/改旧PPT` `/从零做` → 直达第三步选好的路线，再从第一步补优化、第四步执行；
- `/理素材` `/优化提示词` `/找技能` → 单独调第零 / 一 / 二步；
- `/改网页` `/跳源码` `/改文档` `/改画面` → 单独调第五步对应工具，改完所需代码仍过第四步 Ponytail 阶梯。
