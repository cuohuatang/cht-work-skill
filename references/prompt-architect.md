# 提示词架构师细则（V0.03 嫁接 / V0.04 加硬约束，流程第一步 / V0.10 新增 /优化提示词按钮直达）

配套主 `SKILL.md` 的「第一步」。解决两个问题：**用户不会写提示词**，以及**不是所有输入都该优化提示词**。

> **V0.04 核心**：命中「禁止优化清单」时，禁止优化、禁止输出两版模板、禁止技能检索，直接回应或执行。只有任务型且未命中清单，才产出两版提示词。

## 1. 元提示词原文（一字不改，可直接复制）

```
你现在是顶级的AI提示词架构师，我接下来只告诉你使用场景和用途。你要自动完成四件事。一、补齐我没说出口的隐性需求，自动加上角色设定、风格约束、输出格式。二、出两个版本，精简通用版和高阶顶配版。三、用清晰的结构化排版，不废话，不闲聊，不凑字数。四、自动适配ChatGPT、claudecode、豆包、deepseek harness.kimi等等所有AGENT智能体，规避逻辑漏洞和无效指令。
```

## 2. 用户补充的边界约束原文（V0.04 新增，一字不改）

```
特别注意：不优化的提示词：寒暄致谢、纯事实问答 / 翻译 / 摘要、「继续 / 换成蓝色」这类延续性修改、用户已点名技能或文件、只要判断不要优化提示
任务型：下任务、归纳总结、生成、安装、修复、转换、推送、产出文件等等重要任务的事情，就需要优化提示词，不是所有输入的话都要优化你明白我的意思吧。
```

## 3. 禁止优化清单（硬约束，先于一切）

命中任一项 → **禁止优化提示词、禁止输出两版模板、禁止技能检索**，直接回应或直接执行。

| 禁止优化类 | 例子 | 判定信号 |
| --- | --- | --- |
| 寒暄致谢、闲聊、情绪表达 | 「早上好」「谢谢」「今天累死了」 | 无可执行任务、无产出物 |
| 纯事实问答 / 翻译 / 摘要 | 「AGPL 和 MIT 差在哪」「这段翻成英文」「把这段文字缩成 200 字」 | 答案可由已有知识或给定文本直接给出 |
| 延续性修改 | 「继续」「换成蓝色」「再补一页」「你明白我的意思吧」 | 任务上下文已建立，是对既有结果的增量调整 |
| **用户已点名技能或文件** | 「用 cht-work-skill 做」「按这个 README 改」 | 复用对象 / 操作对象已指定 |
| 只要判断，不要产出 | 「这个方案行不行」「帮我看看有没有坑」 | 无交付物、无优化需求 |

### 任务型（必须优化提示词）

下任务、归纳总结、生成、安装、修复、转换、推送、产出文件等**重要任务**。示例：第一次下任务需求、做一份新 PPT、把一组材料归纳成报告、安装技能、修复脚本、转换格式、推送仓库、生成并交付文件。

### 边界辨析：纯摘要 ≠ 归纳总结

| 场景 | 归类 | 处理 |
| --- | --- | --- |
| 把给定文本缩短 / 复述，不产出新结论 | 纯摘要 → 禁止优化 | 直接摘要 |
| 对一组材料做结构化归纳，产出结论、报告、表格、文件 | 归纳总结 → 任务型 | 先优化提示词 |

### 判定顺序（不可颠倒）

```
1. 命中禁止优化清单？ → 是：直接回应/执行，结束；不得出现两版模板
2. 否 → 属于任务型？   → 是：执行第一步（四件事，出两版）
3. 否 → 直接回应，不优化
```

**验收条款**：命中禁止清单时，输出中不得出现「精简通用版」「高阶顶配版」「隐性需求补齐」「已规避的漏洞」等优化产物；交付说明改为标注命中的禁止类别。

## 4. 四件事的可执行拆解（仅任务型执行）

| 原文条款 | 落地规则 | 可观测验收 |
| --- | --- | --- |
| 一、补齐隐性需求 | 补齐角色设定、目标受众、风格约束、输出格式、验收标准、边界条件；缺失项按最保守默认值处理并逐条标注假设；**不向用户反问** | 输出「隐性需求补齐」表，含「项 / 补齐内容 / 依据」三列 |
| 二、出两个版本 | 精简通用版 ≤120 字、单段、可直接复制；高阶顶配版分段结构化，含角色 / 上下文 / 任务拆解 / 约束 / 输出规格 / 验收清单 / 负面清单 | 恰好两个代码块，不出现第三版 |
| 三、结构化排版 | Markdown 标题 + 列表 + 表格；禁止寒暄、解释性铺垫、鼓励语、凑字数的复述 | 全文无「很高兴帮你」「让我解释一下」类句子 |
| 四、适配所有智能体 + 规避漏洞 | 平台中立语法、不依赖特定工具名、不写不可观测要求；逐条排查并修正 6 类漏洞 | 输出「已规避的漏洞」清单，逐条对应第 6 节 |

## 5. 跨智能体适配矩阵

| 目标 | 用哪版 | 适配处理 |
| --- | --- | --- |
| ChatGPT / 豆包 / DeepSeek 等对话框 | 精简通用版 | 单段自然语言，无命令、无工具依赖 |
| Claude Code / Codex / WorkBuddy 等 Agent | 高阶顶配版 | 保留可执行命令与文件路径，任务拆解成可验收条目 |
| Kimi / harness 类智能体外壳 | 高阶顶配版 | 不写平台专有语法与斜杠命令，用自然语言 + 代码块表达 |
| 所有平台通用 | — | 不写「你必须感到」「尽量好看」等不可观测要求；不假定某个工具一定存在 |

## 6. 逻辑漏洞负面清单（逐条排查）

1. **目标冲突**：同一份指令里出现互斥要求。
2. **循环依赖**：完成指令需要先有另一份指令才能生成（本技能用内置元提示词原文规避）。
3. **不可验证形容词**：「高级感」「好用」「尽量」→ 改成可验收条目。
4. **重复指令**：同一规则在多处重复且版本不一致 → 合并为单一出处。
5. **越权假设**：假定某个工具 / 令牌 / 目录已存在 → 显式写成前置依赖并给验证命令。
6. **范围过宽（V0.04 新增）**：不区分对话类型就全量优化，把寒暄、翻译、延续性修改也套进元提示词 → 用第 3 节硬约束清单限定适用范围。

## 7. 衔接规则

优化后的提示词是**后续所有步骤的唯一输入**：第二步检索关键词取自高阶顶配版里的「任务与能力描述」（中英各一组）；第三步路线判定依据优化后的「用途 + 素材 + 交付格式」。不拿用户原始口语需求直接检索或选路线。命中禁止优化清单时，第二步一并跳过。
