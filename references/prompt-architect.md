# 提示词架构师细则（V0.03 嫁接，流程第一步）

配套主 `SKILL.md` 的「第一步」。解决的问题：**用户想用 AI 干活，但不会写提示词**——先把口语化的使用场景和用途，变成能直接复制给任何 AI 的结构化提示词，再动手执行。

## 1. 元提示词原文（一字不改，可直接复制）

```
你现在是顶级的AI提示词架构师，我接下来只告诉你使用场景和用途。你要自动完成四件事。一、补齐我没说出口的隐性需求，自动加上角色设定、风格约束、输出格式。二、出两个版本，精简通用版和高阶顶配版。三、用清晰的结构化排版，不废话，不闲聊，不凑字数。四、自动适配ChatGPT、claudecode、豆包、deepseek harness.kimi等等所有AGENT智能体，规避逻辑漏洞和无效指令。
```

## 2. 四件事的可执行拆解

| 原文条款 | 落地规则 | 可观测验收 |
| --- | --- | --- |
| 一、补齐隐性需求 | 补齐角色设定、目标受众、风格约束、输出格式、验收标准、边界条件；缺失项按最保守默认值处理并逐条标注假设；**不向用户反问** | 输出「隐性需求补齐」表，含「项 / 补齐内容 / 依据」三列 |
| 二、出两个版本 | 精简通用版 ≤120 字、单段、可直接复制；高阶顶配版分段结构化，含角色 / 上下文 / 任务拆解 / 约束 / 输出规格 / 验收清单 / 负面清单 | 恰好两个代码块，不出现第三版 |
| 三、结构化排版 | Markdown 标题 + 列表 + 表格；禁止寒暄、解释性铺垫、鼓励语、凑字数的复述 | 全文无「很高兴帮你」「让我解释一下」类句子 |
| 四、适配所有智能体 + 规避漏洞 | 平台中立语法、不依赖特定工具名、不写不可观测要求；逐条排查并修正目标冲突、循环依赖、不可验证形容词、重复指令、越权假设 | 输出「已规避的漏洞」清单，逐条对应 5 类漏洞 |

## 3. 跨智能体适配矩阵

| 目标 | 用哪版 | 适配处理 |
| --- | --- | --- |
| ChatGPT / 豆包 / DeepSeek 等对话框 | 精简通用版 | 单段自然语言，无命令、无工具依赖 |
| Claude Code / Codex / WorkBuddy 等 Agent | 高阶顶配版 | 保留可执行命令与文件路径，任务拆解成可验收条目 |
| Kimi / harness 类智能体外壳 | 高阶顶配版 | 不写平台专有语法与斜杠命令，用自然语言 + 代码块表达 |
| 所有平台通用 | — | 不写「你必须感到」「尽量好看」等不可观测要求；不假定某个工具一定存在 |

## 4. 逻辑漏洞负面清单（第四步要逐条排查）

1. **目标冲突**：同一份指令里出现互斥要求（例：既要「适配任何 AI」又写「仅 Claude Code 可用」）。
2. **循环依赖**：完成指令需要先有另一份指令才能生成（本技能用内置元提示词原文规避）。
3. **不可验证形容词**：「高级感」「好用」「尽量」→ 改成可验收条目。
4. **重复指令**：同一规则在多处重复且版本不一致 → 合并为单一出处。
5. **越权假设**：假定某个工具 / 令牌 / 目录已存在 → 显式写成前置依赖并给验证命令。
6. **无效指令**：要求模型做无法观测或无法执行的事（「理解我的意图」「发挥创意」）→ 删除或转成具体约束。

## 5. 衔接规则（关键）

优化后的提示词是**后续所有步骤的唯一输入**：

- 第二步检索关键词取自高阶顶配版里的「任务与能力描述」，中英各一组。
- 第三步路线判定依据优化后的「用途 + 素材 + 交付格式」。
- 不拿用户原始口语需求直接检索或选路线。
- 闲聊、纯问答、延续性对话按主文件「执行前判定」跳过本步与第二步。
