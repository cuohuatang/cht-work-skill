# Ponytail 代码最小化阶梯细则（V0.08 嫁接，流程第四步 / V0.10 衔接快捷按钮）

配套主 `SKILL.md` 的「第四步 · 执行编排」。解决一个前面四步都没覆盖的问题：**前三步和 UFO 编排解决「做什么、用什么、走哪条、怎么组织活」，但没有规范「具体写代码 / 改 HTML·CSS·JS 时，怎么写得最少、不把简单需求过度工程」**。这一层借鉴开源 skill Ponytail 的七级决策阶梯，只取方法论，不引入其运行时。

## 1. 来源与定位

- 来源：<https://github.com/DietrichGebert/ponytail>，MIT，约 19.4 万星，主分支 `main`。本质**就是一个 prompt skill**——核心是 `skills/ponytail/SKILL.md` 一份文件，精简版是 `AGENTS.md`；其余仓库内容是把这份 prompt 装进不同 AI 编程客户端的适配层。
- 人设：一个「懒人资深开发」——你说五十行，他不说废话，一行替换掉。「**The best code is the code you never wrote.**」
- 在本技能的层次定位：

| 层 | 复用对象 | 由谁负责 |
| --- | --- | --- |
| **技能层** | 现成 skill（相似度 ≥ 0.90 直接复用） | 第二步 find-skills |
| **代码层** | 代码库 / 标准库 / 平台原生 / 现有依赖 | 本细则（Ponytail 七级阶梯） |

两级是同一精神「**别重复造轮子**」在不同粒度的落地：**先问有没有现成技能（第二步），再问有没有现成代码（本层），都没有才自己写**。

## 2. 七级决策阶梯（核心，写代码前逐级判断，命中即停）

阶梯在**理解问题之后**才跑，不是替代理解：先读改动涉及的代码、摸清真实调用流，再选级。懒在解法，不懒在读代码。

| 级 | 判断 | 命中动作 | 网页 PPT 场景例子 |
| --- | --- | --- | --- |
| 1 | 这段代码需要存在吗？ | 不需要 → **不写**（YAGNI） | 用户要一页静态介绍，别先搭一套组件框架 |
| 2 | 代码库里已有可复用的吗？ | 有 → **复用**，别重写（含本仓库 `scripts/` / `assets/` / 模板 / `references/`） | 已有 `viewport-base.css` 就别重写舞台基准 |
| 3 | 标准库 / 语言内置能做到吗？ | 能 → 用内置 | 日期输入用原生 `<input type="date">`，不引日期库 |
| 4 | 平台 / 浏览器原生特性能做到吗？ | 能 → 用原生 | 折叠用 `<details>`、动画用 CSS，不引 JS 库 |
| 5 | 已装依赖里有吗？ | 有 → 用现成依赖，**不新增** | 模板包已有图标方案就别再引 icon 库 |
| 6 | 能一行搞定吗？ | 能 → **就一行** | 单行 CSS 能解决的别包成函数 |
| 7 | 以上都不行 | 才写**最小可行实现**；有逻辑就留**一个小测试** | 真需要自定义动效才写，并留一个校验脚本 |

## 3. 不可砍的底线（lazy ≠ negligent）

精简的是重复抽象、多余包装、跑不通的无效逻辑，**不是**下面这些：

- 信任边界校验（trust-boundary validation）
- 数据丢失处理（data-loss handling）
- 安全（security）
- 可访问性（accessibility）
- 错误处理（error handling）

带分支 / 循环 / 解析 / 金额 / 安全的逻辑，**留一个小测试**再走。每轮交付结尾说明「**跳过了什么、没检查什么、有什么风险**」，不静默省略。

## 4. 四档强度（本技能只取精神，不要求用户装插件）

| 模式 | 场景 | 本技能对应态度 |
| --- | --- | --- |
| `lite` | 新项目起步，规则松一点保速度 | 快速出样稿阶段可放宽 |
| `full` | 默认，日常开发 | **本技能默认用这一档的精神** |
| `ultra` | 遗留代码清理、技术债审计、追求极致精简 | 审改 / 重构旧 deck 时可加强 |
| `off` | 基准测试对照组 | 需要「放开写」对照时才用 |

> 本技能**不要求用户安装 Ponytail 插件、不切换它的模式、不引入生命周期钩子 / 命令系统**；只把「写代码前过阶梯」作为默认纪律写进流程。想单独用 Ponytail 本体的人，按官方仓库自行安装。

## 5. 官方命令对照（仅记录，不纳入本技能命令链）

| 命令 | 作用 | 本技能是否引入 |
| --- | --- | --- |
| `/ponytail [lite\|full\|ultra\|off]` | 设强度 / 关闭 | 否（用第 4 节默认精神替代） |
| `/ponytail-review` | 审当前 diff 的过度工程 / bug / 安全 | 否（第五步反馈工具有自己的路由） |
| `/ponytail-audit` | 全仓审计，按重要性排序 | 否 |
| `/ponytail-debt` | 收集 `shortcut:` 注释成台账 | 否 |
| `/ponytail-gain` | 显示基准记分板 | 否 |
| `/ponytail band ...` | Claude Code 专用的成本 / token 显示条 | 否 |

命令需要支持 skill 的宿主（Claude Code / Codex / Devin CLI / OpenCode / Gemini 等）；指令式适配（Cursor 规则文件 / Windsurf / Cline / Copilot / Kiro）只加载常驻规则、不带命令。这些形态差异进一步说明**为何不把命令系统搬进本 skill**——会破坏「不挑 Agent」。

## 6. 诚实数据口径（必须按官方 README，别用二手宣传语）

官方 v5 基准（Claude Code，同一 agent 装 / 不装 skill，39 个任务含真实 FastAPI + React 仓库，Opus 5.5，每任务 5 次）：

| 指标 | v5 相对无 skill 基线 |
| --- | --- |
| 代码量 | **-53%** |
| Token | **-45%** |
| 成本 | **-26%** |
| 时间 | **-27%** |
| 风险逻辑带测试率 | **98%**（无 skill 68%） |
| 注入 bug 被自家测试抓到率 | 66%（无 skill 46%） |

**纠正一个常见误传**：网传「Token 消耗降 94%」是把**个别「重造轮子」任务上代码量的峰值降幅**（如日期选择器 404 行→23 行）误当成 Token 平均降幅。官方 v4/市场页的口径是代码 -54%（峰值到 94%）、Token -22%；**v5 是代码 -53% / Token -45%**。本技能转述时一律按官方 v5 口径，不写「Token 降 94%」。

## 7. 与前后步骤的关系

- **第二步（技能检索）**：技能层复用在前，代码层复用在后；「有没有现成 skill」和「有没有现成代码」是两个不同问题，不互相替代。
- **第三步（选路线 / 分叉）**：路线未定前不写实现代码，阶梯也无从跑；选定 A / B 路线后才在第四步写代码时启用。
- **UFO 编排范式（同层）**：UFO 管任务怎么拆、怎么并行、失败怎么恢复；Ponytail 管每个写代码的 AppAgent 子任务内部怎么写得最少。二者是编排层 × 代码纪律，正交互补。
- **第五步（视觉反馈）**：交付后圈选反馈需要改代码时，改的那段同样过七级阶梯；第五步选工具与本步写代码是两个独立环节。

## 9. V0.09 衔接补充（第零步素材工作台）

V0.09 在流程最上游新增可选「素材工作台」（WeKnora），位于第四步之前：第零步把散落多格式素材整理成**带引用的知识**，第四步的 Ponytail 七级阶梯仍只管「写代码怎么写得最少」——两者是**内容准备 × 代码纪律**的正交关系，互不替代。顺序固定：第零步备料 → 第一至三步决策 → 第四步写代码时过七级阶梯 → 第五步反馈。本细则七级阶梯与数据口径不受 V0.09 影响；WeKnora 只借鉴能力路由、不部署不内置，本技能仍保持 Skill 形态。衔接细则见 `references/weknora-knowledge-workbench.md`。

## V0.10 衔接（快捷按钮）

所有会写 / 改代码的按钮（`/改网页` `/跳源码` 等）在改代码时仍按本细则过七级阶梯，安全 / 校验 / 可访问性不砍，数据口径按官方 v5（代码 -53% / Token -45%，别说成 Token 降 94%）。按钮只是入口，阶梯是内部执行纪律，不单独建按钮。按钮清单见 `references/quick-commands.md`。
