# 第三步中间分叉细则（V0.07 嫁接）

本文件是主 `SKILL.md` 第三步「选路线」的细则，规范**低置信度时分叉让用户选**的机制。核心原则一句话：

> **分叉是给模糊地带的选项，不是给用户的问卷。** 确定性高就直达，只有真模糊才弹选项；一旦分叉，每个选项必须说清「选它会得到什么」。

## 1. 为什么要有这一层

第三步原本是一条确定性路由表：有旧稿 → 路线 A（`frontend-slides`），无旧稿 → 路线 B（`guizang-ppt-skill`），要 `.pptx` → 先讲格式冲突。它覆盖不了「中间地带」：

- 有旧稿，但用户其实想推翻重做；
- 没旧稿，但手上一堆参考图 / 零散素材；
- 只说「做个高级点的 PPT」，没说手上有什么；
- 既出网页 PPT，又要配套讲稿 / 文档；
- 用户自己就一句「我拿不准，你给我几个方向」。

以前这些情况只会硬选一条或直接停下。V0.07 让它在**真模糊**时分叉给用户选，但要克制——不能把「用户不会也能用」的初衷变成「什么都问用户」。

## 2. 触发分叉（满足任一）

| # | 场景 | 例子 |
| --- | --- | --- |
| 1 | 两条路线都站得住 | 有旧稿但想彻底换风格；无旧稿但有参考图 / 素材要融入 |
| 2 | 需求描述模糊、置信度低 | 只说「做个高级点的 PPT」，没交代有无旧稿、什么场景 |
| 3 | 用户明说要选项 | 「给我几个方向」「我拿不准」「你列几个选项」 |
| 4 | 跨类型需求 | 既出网页 PPT，又要配套讲稿 / Word 文档 |

## 3. 不分叉（保持直达）

命中任一条就直接走第三步路线表，不弹选项：

- **判定明确**：旧稿翻新、纯从零、已有 HTML deck 要改、明确要 `.pptx`；
- **命中禁止优化清单**：延续性修改（「继续」「换成蓝色」）、用户已点名技能或文件、寒暄、纯事实问答 / 翻译 / 摘要、只要判断——这些按 V0.04 硬约束直接干活；
- **单一明确交付物**：用户已经把要什么说死了，没有第二种合理解读。

## 4. 分叉呈现规范（每个选项必填，缺一不可）

| 字段 | 要求 | 反例（禁止） |
| --- | --- | --- |
| 选项名 | 一句话说清是哪条路线 / 哪种风格 | 「方案一 / 方案二」这种无信息量标签 |
| **选它会得到什么** | **强制字段**：写清产出物、风格、适合谁，落到用户实际拿到的东西 | 「更高大上」「更有高级感」「效果更好」这类抽象形容词 |
| 推荐标记 | 按置信度标一个「推荐」，附一句为什么 | 把所有选项都标推荐，或都不标 |
| 兜底 | 用户不选 / 说「随便 / 你定」→ 直接走推荐项，绝不停下等 | 弹完选项就停住，非要用户回复 |

### 标准输出骨架

```
判定落在模糊地带，给你两个方向：

A. 改旧稿（推荐：你有旧 PPT）
   选它会得到：保留原文字/图片/备注，换成会动的网页演示，先出 3 张样稿给你挑。
   适合：内容已定稿，只想提升现场观感。

B. 从零做
   选它会得到：按杂志风/瑞士风从零生成，配色用预设主题，自带演讲者模式的网页演示。
   适合：想换叙事结构、推翻重来。

你说「随便」我就按 A 走。
```

写作检查：把每个选项的「选它会得到什么」单独拎出来看——如果一个从没用过本技能的人读完还是不知道自己会拿到什么，就重写，直到他能用一句话复述。

## 5. 与前后步骤的关系

- **与第一步（提示词优化）**：分叉**不改变禁止优化判定**。延续性修改（「把这里改一下」）虽可能需要分叉来定位「这里」指哪版，但它仍属禁止优化类，**不生成两版提示词**。禁止的是「生成两版提示词」，不是「给用户列选项」。
- **与第二步（技能检索）**：分叉发生在第三步路线层，不重复触发检索；只有分叉后冒出新任务域才对那个域单独检索一次。
- **与第四步（执行编排）**：用户选定（或走兜底推荐项）之后，才算路线确定，第四步才按确定的路线拆任务图；不要在路线还没定时就上 DAG。
- **与第五步（视觉反馈）**：分叉选完后正常交付，交付后如需审改再进第五步，两者独立。

## 6. V0.07 实跑留痕（本轮自身）

- **判定**：本轮为延续性修改 + 点名对象，命中 V0.04 禁止优化硬约束 → 禁止优化、禁止生成两版提示词；同时属自迭代工程任务，不在网页 PPT 路由域 → 分叉机制本身是本轮要写入的能力，不是本轮要执行的路由，故本轮**不触发分叉**，直接落地文件。
- **设计决策**：把「选它会得到什么」设为强制字段，正是为了避免用户面对「方案 A / 方案 B」这类抽象选项仍选不动——选项必须落到可复述的产出物。
- **文档落地**：主 `SKILL.md` 第三步新增分叉子节、注意事项第 9 条、交付话术第 6 条、版本表 V0.07 行；本细则新建；README 与既有四份细则补衔接。
- **诚实边界**：分叉仅是本技能的决策规则，不引入任何新工具、新依赖，也不改成 MCP；第五步四工具与外部依赖的状态不受影响。

## 7. V0.08 衔接补充（第四步代码最小化）

V0.08 在第四步嫁接 Ponytail 七级阶梯，位于第三步分叉之后：分叉只决定「走哪条路线 / 哪种风格」，路线定了才在第四步写代码时启用阶梯（先问有无现成代码再写最小实现）。二者独立且顺序固定——**分叉定方向、阶梯管实现**，别在路线还没定就讨论代码怎么写。本细则分叉规则与兜底逻辑不受 V0.08 影响；Ponytail 只借鉴方法论、不改 Skill 形态。衔接细则见 `references/ponytail-minimal-code.md`。
