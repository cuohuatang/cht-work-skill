# 任务前置分流细则（V0.02 嫁接 / V0.03 顺延为第二步）

配套主 `SKILL.md` 的「第二步」。目标：**别重复造轮子**，以及**别把闲聊也拿去检索**。

> V0.03 起，本步骤的检索关键词来自「第一步 · 提示词优化」产出的高阶顶配版，不再使用用户原始口语需求。对话类型判定在主文件「执行前判定」里先过一遍。

## 1. 对话分类

| 类别 | 判定依据 | 优化提示词 | 检索技能 |
| --- | --- | --- | --- |
| 闲聊 / 寒暄 / 致谢 / 情绪表达 | 无可执行任务、无产出物 | 否 | 否 |
| 纯信息类：事实问答、概念解释、翻译、对已有文本做摘要 | 答案可由已有知识或给定文本直接给出 | 否 | 否 |
| 延续性对话：确认、追问、澄清、对上一轮结果提修改意见（「继续」「换成蓝色」） | 任务上下文已建立，需求是增量调整 | 沿用上轮结果 | 沿用上轮结果 |
| 用户已点名技能 / 文件 / 仓库 | 复用对象已指定 | 是 | 否 |
| 只要判断、建议、审阅，不产出文件 | 无交付物 | 否 | 否 |
| **任务型**：生成、安装、修复、转换、推送、分析并产出文件 | 需要动手且可能产生可复用能力 | **是（第一步）** | **是（第二步）** |

判定原则：**看这条消息是否要求「动手做一件可能已有现成解法的事」**，而不是看它长不长、像不像需求。一句「把这份 PPT 转成网页」是任务型，一段很长的吐槽不是。

## 2. 检索动作

依赖全局 `find-skills`（`name: find-skills`）。主源 SkillHub 语义检索，关键词取自第一步高阶顶配版里的「任务与能力描述」：

```bash
curl -s "https://lightmake.site/api/v1/search?q=<URL编码后的优化需求>&limit=10"
```

- 中英文关键词各试一组（SkillHub 支持中文语义检索）。
- 读 `results[].score`，取值 0~1；`score < 0.05` 的结果按 find-skills 的建议忽略。
- SkillHub 无结果时按 find-skills 的兜底顺序：`npx skills find <query>` → `npx clawhub search <query>`。
- 安装前先查本地技能市场 `~/.workbuddy/skills-marketplace/skills`，有同款直接复制，避免重复下载。

## 3. 阈值判定表

| 最高 score | 判定 | 动作 |
| --- | --- | --- |
| **≥ 0.90** | 高相似，现成技能可用 | 直接复用：装好并调用该技能，不再从零实现 |
| 0.60 ~ 0.90 | 相关但不确定 | 列出 3~5 个候选 + 差异说明，用户点名才用 |
| **< 0.60** | 无现成技能 | 自主实现；在执行说明写明「已检索、无高相似技能」 |

`≥ 0.90` 是硬阈值：**达到就复用**，不因为「自己写更快」而跳过。低于 0.60 才允许自主实现，这个判定要留痕，不是凭感觉。

## 4. 留痕格式

每次走完前两步，在交付说明里附：

```
提示词优化：精简通用版 <摘要> ｜ 高阶顶配版 <摘要>
检索词：<中/英关键词> ｜ 最高 score：<数值> ｜ 判定：<≥0.90 复用 / 0.60~0.90 候选 / <0.60 自主实现>
```

历次实测：

| 版本 | 检索词 | 最高 score | 判定 |
| --- | --- | --- | --- |
| V0.02 | 技能发现 优先搜索现成 skill 复用 / github push create repository skill | 0.050 / 0.050 | < 0.60，自主完成迭代 |
| V0.03 | 提示词架构师 优化提示词 两版本 多智能体适配 / prompt architect optimize user prompt two versions multi agent | 0.050 / 0.050 | < 0.60，自主完成迭代 |

## 5. 例外与边界

1. **已匹配能力不重复检索**：用户已明确落在网页 PPT 域时，`cht-work-skill` 自带的 A / B 两条路线就是现成能力，直接进第三步选路线。
2. **新任务域才补检索**：一次任务里冒出别的能力域（推送 GitHub、生成配图、写测试），只对那个新域单独检索一次，不要整轮重搜。
3. **延续性对话不重搜**：用户说「继续」「改成 XX」，沿用上一轮的判定结果，除非引入全新任务域。
4. **检索不是审批**：不要因为检索结果就停下来反问用户「要不要用」，`≥ 0.90` 直接复用、`< 0.60` 直接实现；只有 0.60~0.90 的候选区间才需要用户点名。
5. **不检索 ≠ 不判断**：不检索的对话仍要判断意图，只是跳过 find-skills 这一步。
6. **第一步优先**：无论是否检索，任务型请求都先执行第一步的提示词优化；优化结果即使不用于检索，也用于明确用途与交付格式。

## 6. 前置依赖安装

```bash
# 全局安装（目录名严格等于 SKILL.md 里 name 字段）
cp -r <find-skills 源目录> ~/.codebuddy/skills/find-skills/

# 验证
grep -rl "^name: find-skills" ~/.codebuddy/skills/*/SKILL.md
```

未安装时先补齐再执行第二步；find-skills 的 `SKILL.md` 含 `name` 与 `description` 两个字段，符合项目安装规范。
