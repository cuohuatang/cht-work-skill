# 任务前置分流细则（V0.02 嫁接 / V0.03 顺延第二步 / V0.04 对齐禁止优化硬约束 / V0.05 衔接第四步执行编排）

配套主 `SKILL.md` 的「第二步」。目标：**别重复造轮子**，以及**别把闲聊也拿去检索**。

> V0.04 起，本步骤与第一步共用同一套「禁止优化清单」硬约束：命中禁止清单时，第一步不优化、第二步不检索，直接执行。检索关键词来自第一步产出的高阶顶配版，不使用用户原始口语需求。

## 1. 对话分类（硬性）

| 类别 | 判定依据 | 优化提示词 | 检索技能 |
| --- | --- | --- | --- |
| 寒暄致谢 / 闲聊 / 情绪表达 | 无可执行任务、无产出物 | **禁止** | 否 |
| 纯事实问答 / 翻译 / 摘要 | 答案可由已有知识或给定文本直接给出 | **禁止** | 否 |
| 延续性修改（「继续」「换成蓝色」「再补一页」） | 任务上下文已建立，需求是增量调整 | **禁止** | 否 |
| **用户已点名技能 / 文件 / 仓库** | 复用对象或操作对象已指定 | **禁止** | 否 |
| 只要判断、建议、审阅，不产出文件 | 无交付物 | **禁止** | 否 |
| **任务型**：下任务、归纳总结、生成、安装、修复、转换、推送、产出文件 | 重要任务，需要动手且可能产生可复用能力 | **是（第一步）** | **是（第二步）** |

判定原则：看这条消息是否要求「动手做一件可能已有现成解法的事」，而不是看它长不长、像不像需求。一句「把这份 PPT 转成网页」是任务型，一段很长的吐槽不是。

### 边界辨析：纯摘要 ≠ 归纳总结

| 场景 | 归类 | 处理 |
| --- | --- | --- |
| 把给定文本缩短 / 复述，不产出新结论 | 纯摘要 → 禁止优化 | 直接摘要 |
| 对一组材料做结构化归纳，产出结论、报告、表格、文件 | 归纳总结 → 任务型 | 先优化提示词 |

判定顺序：**先查禁止清单（命中即停）→ 未命中再看是否任务型（是则优化 + 检索）→ 其余直接回应**。

## 2. 检索动作

依赖全局 `find-skills`（`name: find-skills`）。主源 SkillHub 语义检索，关键词取自第一步高阶顶配版里的「任务与能力描述」：

```bash
curl -s "https://lightmake.site/api/v1/search?q=<URL编码后的优化需求>&limit=10"
```

- 中英文关键词各试一组（SkillHub 支持中文语义检索）。
- 读 `results[].score`，取值 0~1；`score < 0.05` 的结果按 find-skills 的建议忽略。
- SkillHub 无结果时按 find-skills 的兜底顺序：`npx skills find <query>` → `npx clawhub search <query>`。
- 安装前先查本地技能市场 `~/.workbuddy/skills-marketplace/skills`，有同款直接复制，避免重复下载。

## 3. 阈值判定表

| 最高 score | 判定 | 动作 |
| --- | --- | --- |
| **≥ 0.90** | 高相似，现成技能可用 | 直接复用：装好并调用该技能，不再从零实现 |
| 0.60 ~ 0.90 | 相关但不确定 | 列出 3~5 个候选 + 差异说明，用户点名才用 |
| **< 0.60** | 无现成技能 | 自主实现；在执行说明写明「已检索、无高相似技能」 |

`≥ 0.90` 是硬阈值：**达到就复用**，不因为「自己写更快」而跳过。低于 0.60 才允许自主实现，这个判定要留痕，不是凭感觉。

## 4. 留痕格式

任务型走完前两步，在交付说明里附：

```
提示词优化：精简通用版 <摘要> ｜ 高阶顶配版 <摘要>
检索词：<中/英关键词> ｜ 最高 score：<数值> ｜ 判定：<≥0.90 复用 / 0.60~0.90 候选 / <0.60 自主实现>
```

命中禁止优化清单时改为：

```
本轮判定为禁止优化类（<命中类别>），未生成两版提示词，未做技能检索，直接执行。
```

## 7. V0.05 衔接补充

主 `SKILL.md` 新增「第四步 · 执行编排」（UFO² / UFO³ 范式）。本步骤（第二步检索）的职责与阈值表**完全不变**，补充两点衔接：

1. **新任务域单独检索**：V0.05 本轮把「桌面 Agent 编排范式」当作新任务域，按第 5 节第 2 条单独检索一次（两组关键词最高 score 均 0.050），结论为自主实现。该留痕同时写入 `references/ufo-execution-paradigm.md` 第 6 节。
2. **非 PPT 路由域的判定要留痕**：本轮属技能自迭代 / 嫁接新能力，不落第三步的网页 PPT 路由表，按主文件第三步说明走自主实现路径，并把「不属于 PPT 路由域」写进留痕，避免为凑流程强套 A / B 路线。
3. 第二步产出的「检索结论 + 优化后的高阶顶配版」一并作为第四步拆任务图、定验收口径的输入；细则见 `references/ufo-execution-paradigm.md`。

## 5. 例外与边界

1. **已匹配能力不重复检索**：用户已明确落在网页 PPT 域时，`cht-work-skill` 自带的 A / B 两条路线就是现成能力，直接进第三步选路线。
2. **新任务域才补检索**：一次任务里冒出别的能力域（推送 GitHub、生成配图、写测试），只对那个新域单独检索一次，不要整轮重搜。
3. **延续性对话不重搜**：用户说「继续」「改成 XX」，沿用上一轮的判定结果，除非引入全新任务域。
4. **检索不是审批**：不要因为检索结果就停下来反问用户「要不要用」，`≥ 0.90` 直接复用、`< 0.60` 直接实现；只有 0.60~0.90 的候选区间才需要用户点名。
5. **不检索 ≠ 不判断**：不检索的对话仍要判断意图，只是跳过 find-skills 这一步。
6. **硬约束优先于第一步**：命中禁止优化清单时，第一步不生成两版提示词，本步骤也无输入可检索，两者一并跳过；不得为了凑流程而强行优化或检索。

```bash
grep -rl "^name: find-skills" ~/.codebuddy/skills/*/SKILL.md
```
