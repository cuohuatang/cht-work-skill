帮我用网页标注的方式改前端。工具选择与完整流程按 **cht-work-skill** 第五步（`references/visual-feedback-routing.md`）执行。

用户输入：$ARGUMENTS

## 我要做的事

1. **确认前端项目根目录**并启动必要服务：
   - 在项目根目录启动 companion：``npx pinta-companion .``（保持终端运行，默认监听 127.0.0.1:7878）。
   - 确认 Pinta MCP 已配置：``codex mcp list`` 看是否有 pinta；没有就用 ``codex mcp add pinta -- npx -y -p pinta-companion pinta-mcp`` 配一次。
   - 提醒用户启动前端 dev server（如 ``npm run dev``），浏览器打开 localhost 页面，点工具栏 Pinta 图标**打开右侧边栏**，看到 `Connected` 即连通。
2. **告诉用户怎么标注**（右边栏直接操作）：按 `Alt + S` 进入 Select 模式 → 点选要改的网页元素 → 在批注框写具体修改意见（如「按钮背景改黑色、加圆角、尺寸放大」，别写「优化一下」）→ `Add annotation` → 侧边栏底部 `Send to agent`。标注工具还有 Arrow / Rect / Pen / Pin，改按钮文字卡片用 Select 即可。
3. **读取批注 session**：检查 Pinta 中待处理的 session，读出圈选的元素（DOM/Selector/附近文本）与修改要求。
4. **先 Plan 后改**：列出准备改哪些文件、什么样式、哪些组件，等用户确认后再执行；按 Ponytail 七级阶梯写最小代码（校验/安全/可访问性不砍）。
5. **刷新验证**：改完提醒用户刷新页面看效果（有 HMR 会自动变）。

## 何时升级到 Inspecto（进阶补位）

如果用户需要以下任一项，改用 Inspecto 而不是 Pinta：
- `Alt + 点击` 跳到准确源码行；
- 任务时间线（session 状态实时回传侧边栏：领取/处理中/完成/忽略）；
- `prompts.json` 自定义工作流按钮（如 Deploy Preview / Review & PR）。

Inspecto 接入：在项目根目录 ``npm install -D @inspecto-dev/cli``（由我引导配置），重启 dev server 后打开浏览器，用 Quick Jump / Inspect Mode / Annotate Mode 三模式之一。**配置细节查官方文档，不凭空编造 `prompts.json` 字段。**

如果用户没给项目路径或 URL，先问：要改的前端项目在哪个目录？页面 URL 是什么？用 Pinta 还是直接上 Inspecto（需要跳源码行/时间线）？

## 提醒

这是**前端源码**链路，只处理 DOM / 组件；PPT / Word / Markdown / 图片文档不走这里（用 `/改文档`），截图 / AI 生图 / 画面走 `/改画面`。需要 Node.js 20+，companion 必须在正确项目目录。
