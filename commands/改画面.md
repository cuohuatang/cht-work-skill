帮我用画面标注的方式改图。工具与流程按 **cht-work-skill** 第五步（`references/visual-feedback-routing.md`）执行，用 **EditHere**。

用户输入：$ARGUMENTS

## 我要做的事

1. **确认画面来源并打开 EditHere**：EditHere 是 **Qt 桌面应用**（Windows / macOS）+ companion skill + `edithere-cli`，**不是浏览器右边栏**——如实告诉用户它在桌面应用里标注。让用户打开目标画面（截图 / AI 生图 / 视频帧 / 游戏 HUD / 桌面 UI / 图表 / 演示页 / 设计稿），若项目里有 `edithere-cli` 按其命令启动。官方入口 <https://github.com/Inginnng/EditHere>（MIT）；本技能不内置该应用，未安装时给出官方获取方式、不阻塞。
2. **告诉用户怎么标注**（桌面应用里直接操作）：智能选块 / 点 / 框 / 全局意见 + 「大爆炸」拖动布局；视频/动画按帧批注会带时间戳。原图完整保留，批注与坐标独立导出。
3. **读取结构化反馈**：拿到导出的**原图 + 编号坐标 + 布局变化 JSON**（`region` / `global` 坐标、`movement` 移动前后矩形、编号意见；格式见上游 `feedback-minimal-v4.schema.json`）。直接由我读图 + JSON 解析意图，**无需另配 API Key**（密钥存系统凭据库，不写进项目或 JSON）。
4. **执行修改并核验**：按标注意图改对应内容（图片局部 / 前端画面 / 演示页），透明空洞等由我结合项目实现补；改完对照原图与坐标核验。

## 关键边界（如实说明）

- EditHere **不调用模型、不写代码**，只导出结构化反馈；不做语义抠图、不自动补背景、不执行视频剪辑。
- 不绑模型、不绑 DOM——屏幕上能看到就能标，这是它相对 Pinta（绑前端 DOM）的优势。
- 这是**画面**链路：改前端源码 UI 用 `/改网页`；网页/PPT/Word/Markdown 文档审改用 `/改文档`。

如果用户没给图片/画面路径，先问：要标注哪张图或哪段画面（给路径）？是静态图、AI 生图、视频帧还是游戏/桌面 UI？
