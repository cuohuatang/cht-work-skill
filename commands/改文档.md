帮我用原位标注的方式审改文档。工具与流程按 **cht-work-skill** 第五步（`references/visual-feedback-routing.md`）执行，用 **human-review**（Skill 形态，不是 MCP）。

用户输入：$ARGUMENTS

## 我要做的事

1. **打开文档审改面板**：根据目标类型选命令——
   - 本地 HTML 文件：``npx -y human-review path/to/file.html``
   - 本地开发页面：``npx -y human-review http://localhost:3000/wiki``
   - 首次使用可全局配置：``npx -y human-review setup --global``
   打开后用户会在真实浏览器里看到文档，像用 Google Docs 一样操作。
2. **告诉用户怎么标注**（浏览器里直接操作）：直接改字、加粗、建列表、拖图片、选中短语留言、对图片/区块批注、删除；完成后点 **Send** 一次性回传全部修改与评论。这是原位锚定的，不用在聊天框里描述"第几段"。
3. **接收反馈并应用回源文件**：HTML 的直接编辑/图片缩放会自动保存；**Markdown 与 localhost 页面必须点 Send，由我把修改应用回源文件**（Markdown 文件本身不被改写，批注引用的是渲染后文本）。用 ``npx -y human-review poll <目标>`` 阻塞等待用户点 Send，收到后逐条落回源文件。
4. **验证**：改完读回源文件或页面确认改动正确落地，不漏批注。

## 关键边界（如实说明）

- human-review 适用：文档、方案、落地页、本地 Web 应用、多页网站；HTML / Markdown / localhost 页面均可。
- **它不替你做产品决策，也不等于代码 Review**——视觉改对不代表性能 / 可访问性 / 响应式 / 业务逻辑没问题。
- 要求 Node.js 20+，npm 包约 0.4.0。
- 这是**文档/网页内容**审改链路：改前端源码 UI 用 `/改网页`；截图 / AI 生图 / 视频 / 游戏 HUD 等画面用 `/改画面`（human-review 主要处理网页与文档文本）。

如果用户没给目标文件/URL，先问：要审改哪个文档或页面（给路径或 localhost 地址）？想重点改什么？
